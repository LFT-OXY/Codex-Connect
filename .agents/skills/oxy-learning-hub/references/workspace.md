# 教学工作区

## 定位与恢复

按以下顺序定位工作区：

1. 用户明确指定目录：使用该目录；
2. 用户提供的一组工作区文件拥有共同父目录，且其中有 `MISSION.md`：使用该父目录；
3. 当前目录已有 `MISSION.md`：继续该教学工作区；
4. 当前总结已经保存到含 `SUMMARY.md` 的目录：升级时复用该目录；
5. 用户要求“继续上次教学”但没有给路径：在当前项目内查找含 `MISSION.md` 的
   `atlas-*` 目录；单个结果直接使用，多个结果只询问一次；
6. 否则在当前项目根目录创建：

```text
atlas-{YYYYMMDD}-{safe-topic}/
```

标题保留可读字符；目录名只使用路径安全字符。无法可靠提取主题时使用
`untitled`。不要在技能安装目录里保存用户课程。

总结升级教学时，把已生成的总结保存为 `SUMMARY.md`。同一会话中的原材料和概念
地图直接复用；跨会话恢复时从 `SUMMARY.md`、`RESOURCES.md` 和用户重新指定的材料
恢复，不重新抓取仍然可用的本地内容。

## 目录结构

首次教学访谈的信息完整后，直接创建或初始化工作区，不需要额外确认；先创建
`assets/` 并复制基础样式和交互脚本，其他文件和目录继续按需创建。若本轮要修改已有
Mission，必须在用户确认变更后再更新工作区状态：

```text
atlas-{date}-{topic}/
├── SUMMARY.md
├── MISSION.md
├── RESOURCES.md
├── GLOSSARY.md
├── NOTES.md
├── lessons/
│   └── 0001-topic.html
├── reference/
│   └── topic-cheatsheet.html
├── learning-records/
│   └── 0001-insight.md
└── assets/
    ├── course.css
    └── course.js
```

文件用途：

- `SUMMARY.md`：原材料的全局知识地图，也是总结升级教学的桥梁；
- `MISSION.md`：现实目标、成功标准、约束和范围；
- `RESOURCES.md`：可信知识来源和真实实践社区；
- `GLOSSARY.md`：用户已经理解并统一使用的术语；
- `NOTES.md`：教学偏好和不适合放入正式记录的工作备注；
- `lessons/`：每轮一个互动 HTML 课程；
- `reference/`：长期查阅的压缩资料；
- `learning-records/`：有证据支持的学习进展和关键认知变化；
- `assets/`：所有课程共享的样式、测验、模拟器和图表组件。创建课程前必须先读取，
  复用优先；新组件只要可能被第二节课使用，就在第一次出现时沉淀到这里。

## 编号

创建课程或学习记录前，扫描对应目录的最高四位数字并加一：

```text
0001-topic.html
0002-next-topic.html
```

没有目录时从 `0001` 开始。不要覆盖已有课程。创建新课程或参考资料后，更新全部
现有课程中的相对导航链接，确保它们互相可达。

## NOTES.md

以 `# Notes` 开头，下面使用简单的项目符号列表记录：

- 用户当前基础、相关经验和自评把握程度；
- 用户偏好的解释顺序、语言、代码语言、练习密度和课程长度；
- 技术课程的操作系统、工具链、版本和项目环境细节；
- 用户明确不喜欢的教学方式；
- 社区参与偏好；
- 尚未达到学习记录标准、但下一课需要考虑的观察。

正式知识、资源和掌握证据分别进入对应文件，不在 `NOTES.md` 重复。

## 跨会话继续

恢复教学时按顺序读取：

1. `MISSION.md`；
2. 全部仍有效的学习记录，按时间从新到旧阅读；
3. `GLOSSARY.md`；
4. `NOTES.md`；
5. 工作区 `assets/` 中的共享组件；
6. 最近一节课程；
7. 与下一课相关的 `RESOURCES.md` 条目。

然后检查 Mission 是否仍然完整、有效且符合当前方向。有效时用最近发展区选择下一课；
缺失时重新进入自适应访谈并只补问缺口，信息完整后直接继续。方向发生变化时，先说明
拟变更内容并取得用户确认，再更新 Mission。用户要求总结课程时生成 `reference/`
资料，不删除或重置现有状态。

## 完成标准

- 所有课程和状态文件写入用户工作区，而不是技能目录；
- 文件按需创建且编号连续；
- `SUMMARY.md` 能支持总结到教学的升级；
- 跨会话恢复不依赖未保存的聊天上下文；
- 第一课开始前 Mission 信息完整，且起点、主要约束和必要技术环境已记录；
- 修改已有 Mission 时，变更已经得到用户确认。
