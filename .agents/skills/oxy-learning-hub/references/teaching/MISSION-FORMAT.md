# MISSION.md 格式

`MISSION.md` 位于教学工作区根目录，用来记录用户为什么学习这个主题。每一个课程
选择、资源推荐和练习设计都应能追溯到这里。

## 模板

```markdown
# Mission: {主题}

## Why

{1～3 句话描述真实目标。写清学会以后，用户的工作或生活会发生什么变化。}

## Success looks like

- {一个可观察、可验证的能力}
- {另一个可观察能力}

## Starting point

- {当前基础、相关经验和已经掌握的前置知识}

## Constraints

- {时间、预算、截止日期、每次可投入时长或其他限制}

## Environment

- {技术课程的操作系统、工具链、目标版本和项目环境；不适用时省略本节}

## Out of scope

- {当前明确不学习的相邻主题}
```

## 规则

- 一个工作区只服务一个 Mission；无关目标使用另一个工作区。
- 具体目标优先于“理解某主题”这类抽象表达。
- 先从对话中提取已有答案；对仍缺失且会影响课程方向的信息，每轮只问一个聚焦问题，
  持续访谈直到 Mission 完整，不固定问题数量。
- 用户无法明确回答时提供具体选项帮助选择，不替用户静默补全关键目标、基础或约束。
- 首次创建 Mission 时，信息完整后直接写入；不向用户展示 Mission 或 Notes 草稿、
  访谈总结或执行摘要，
  也不额外要求确认。
- 修改已经存在的 Mission 前，先说明拟变更的目标、成功标准、范围或主要约束，得到
  用户确认后再更新；学习结果导致的方向变化写学习记录，外部计划变化写入 `NOTES.md`，
  未确认时保留原 Mission。
- 保持在一屏以内；它是方向，不是项目计划。
