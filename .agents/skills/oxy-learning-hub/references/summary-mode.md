# 总结模式

## 目标

让用户快速建立对材料的完整认识，并留下可以继续追问或升级为教学的知识地图。
总结追求高信息密度，不模拟长期课程。

## 步骤一：界定范围

从用户请求和材料中确定：

- 本轮总结对象；
- 用户最关心的问题；
- 材料能够支持和不能支持的结论；
- 是否需要外部来源补充。

用户没有指定深度时，默认覆盖理解材料所需的核心内容，不扩展成百科全书。

**完成标准**：总结边界清楚，材料缺口已记录。

## 步骤二：建立知识地图

识别材料中的核心概念、关系和关键证据。概念数量由材料决定，不强制归纳成
固定三点。

对每个真正重要的概念，尽量回答：

- 它是什么；
- 为什么存在；
- 如何运作；
- 与其他概念有什么关系；
- 一个具体例子；
- 适用边界或常见误解。

代码材料还要覆盖真实入口、关键符号、调用或数据流、外部依赖和失败边界，
并标明文件路径。文档、论文和文章保留作者原本的论证结构，不强行套用代码模板。

**完成标准**：每个核心概念和关键关系均有来源支撑或明确标为推导。

## 步骤三：生成总结

根据材料是否支持，选用下面的章节；没有内容的章节直接省略：

```markdown
# 标题

## 一句话抓手

## 全局地图

## 核心内容

## 运行机制或论证过程

## 示例与应用

## 边界、误区与反例

## 材料没有回答的问题

## 来源

## 如果你想继续学习
```

“如果你想继续学习”只提供与当前材料相关的入口，例如：

- 进入教学模式，先学习某个关键前置概念；
- 围绕某个实际目标建立课程；
- 把当前最困惑的部分做成第一课。

不要固定生成八个 FAQ、五到八个问题或完整可运行代码。只有它们确实帮助理解时
才加入。

**完成标准**：读者能够复述材料主线，区分事实与推导，并知道下一步可以问什么。

## 来源与准确性

- 材料直接表达的内容可以陈述为事实。
- 从多处材料综合出的结论标明“综合判断”或“推导”。
- 类比用于解释，不充当证据。
- 历史、版本、趋势和现实案例只有经来源支持时才写。
- 找不到可靠来源时写明“未验证”，不补造链接、作者或代码行为。

## 输出

严格按照进入总结模式时确认的多选结果执行：

- **直接在对话中展示**：在当前回复中返回完整 Markdown；
- **生成 Markdown 文档**：读取 `publishing.md` 并写入 `SUMMARY.md`；
- **生成 HTML 单文件**：读取 `publishing.md` 并生成 `SUMMARY.html`；
- **写入 Outline**：读取 `publishing.md` 并创建或更新 Outline 文档。

多个选项同时选择时全部执行，未选择的分支不执行。不要因为已经写入文件就省略用户
同时选择的对话正文。保存总结时使用教学工作区兼容的 `SUMMARY.md`，便于以后无损
升级为教学模式。
