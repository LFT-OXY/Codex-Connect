# 教学模式

教学模式是跨多轮、可跨会话的学习过程。目标不是让用户读完一篇长文，而是让他
逐步形成能够提取、应用和迁移的长期记忆。

## 教学闭环

每轮遵循同一闭环：

```text
Mission → 当前水平 → 单点课程 → 主动练习 → 用户反馈 → 更新状态 → 下一课
```

### Mission 与启动访谈

所有教学决策都要追溯到用户的现实目标。已有教学工作区且 Mission 仍然有效时直接
恢复状态；新建工作区、Mission 不完整或方向变化时，先完成自适应访谈。

先从当前对话、用户提供的材料和已有状态中提取信息，不重复询问。然后按缺口逐项确认：

1. **Why**：为什么学习，现实中要解决什么问题；
2. **Success looks like**：学会后能完成哪些可观察、可验证的事情；
3. **Starting point**：当前基础、相关经验和已经掌握的前置知识；
4. **Constraints**：时间、截止日期、预算、每次可投入时长和其他限制；
5. **Environment**：技术课程使用的操作系统、工具链、目标版本和项目环境；
6. **Learning preferences**：偏好的解释顺序、练习密度、语言和课程长度；
7. **Out of scope**：当前明确不追逐的相邻主题。

每轮只问一个聚焦问题，但持续询问直到缺口补齐。问题数由缺失信息决定：信息完整的
请求可以直接开始；“我想学习 Java”这类宽泛请求通常需要多轮。用户说“不确定”时
给出具体选项帮助选择，不替用户静默编造答案。

首次创建 Mission 时，信息足够后直接写入 `MISSION.md`，并把学习起点、技术环境和
教学偏好写入 `NOTES.md`；不向用户展示 Mission 或 Notes 草稿、访谈总结或执行摘要，
也不增加
确认轮次，随后建立资源库并生成第一课。

只有修改已经存在的 Mission 时才需要确认：先向用户说明拟修改的目标、成功标准、
范围或主要约束，得到明确确认后再更新 `MISSION.md`。如果变更是学习结果导致的认知
或目标变化，创建学习记录；如果只是外部计划改变，把变更原因简短记入 `NOTES.md`，
不伪造掌握证据。用户未确认时保留原 Mission，不改变后续教学方向。确认发生在下一轮
时，严格使用当前对话中上一轮已说明的拟变更内容；如果上下文中已没有完整提议，重新
说明具体变更并再次询问，不自行推断缺失字段。

### 最近发展区

每节课前读取 `MISSION.md`、全部仍有效的学习记录、`GLOSSARY.md` 和
`NOTES.md`，判断用户已经掌握什么、正在卡在哪里，以及下一个“刚好有挑战”的
内容是什么。

用户指定了明确困惑时，优先处理该困惑或它缺失的最小前置知识。不要因为材料很长
就从第一章机械讲起。

### 单点胜利

一节课只教授一个紧凑目标，并让用户获得一个可观察的结果，例如：

- 能用自己的话解释一个机制；
- 能预测一段代码的结果；
- 能完成一个实际步骤；
- 能判断一个方案何时适用；
- 能识别并纠正一个常见误解。

课程应短到可以在一次专注中完成。只提供获得该技能所需的知识。

## 知识、技能与智慧

### 知识

知识来自高信任来源。优先使用原始文档、规范、论文、项目源码和公认专家资料，
不能把模型记忆当作证据。在 `RESOURCES.md` 中记录每个来源讲什么、支持哪些关键
结论、被哪些课程使用，以及可信度缺口。

每个关键事实必须能就近追溯到来源：

- 网页、论文和规范在事实后使用链接到来源清单的 `[S1]`、`[S2]` 标记；
- 本地文档标明文件路径和章节；
- 代码结论标明文件路径、符号名和可用的行号；
- 多来源综合结论明确标为“综合判断”，并同时引用相关来源；
- 教学类比明确是类比，不把类比当作事实来源；
- 没有可靠来源的结论标为“未验证”或直接省略。

理解知识时降低无关难度：先给清晰心智模型，再引入术语和细节。

### 技能

技能通过有反馈的练习建立。练习使用适度的困难：

- 主动回忆：先回答，再查看答案；
- 间隔：后续课程重新提取旧知识；
- 交错：掌握基础后，混合相近但不同的场景。

每个练习必须有立即可用的检查方法。选项长度、格式和措辞应尽量对称，避免泄露
答案。

### 智慧

需要真实经验判断的问题，应给出当前可支持的回答，同时建议用户在高质量社区、
真实项目、课程或实践环境中检验。用户不希望加入社区时，把偏好记入 `NOTES.md`。

## 共享 Assets

复用是默认策略。初始化教学工作区时，把本技能的 `assets/course.css` 和
`assets/course.js` 复制到工作区 `assets/`，所有课程通过相对路径加载它们。

每次创建课程前先读取工作区 `assets/`：

- 已有样式、测验、小组件、模拟器和图表辅助代码优先复用；
- 第二节课程也可能使用的组件，第一次出现时就写入 `assets/`；
- 新增可复用组件后，让相关旧课程改用共享组件；
- 课程正文只内联本课独有的内容，不重复内联共享 CSS 或 JavaScript；
- 工作区增长时同步维护组件库，让课程保持统一外观和行为。

## 每节互动 HTML 的结构

使用 `assets/lesson-template.html`，把占位符全部替换；课程位于 `lessons/` 时，
`{{ASSET_PREFIX}}` 使用 `../assets/`。标题区占位符按以下方式填写：

- `{{CRUMB}}`：课程路径，例如 `attention / lesson-03`；
- `{{KICKER}}`：课程类型与预计时长，例如 `互动课程 · 12 分钟`；
- `{{FACTS}}`：使用若干 `<span class="chip">…</span>` 展示前置知识、练习数、
  来源数和单点目标；
- `{{ASIDE}}`：使用若干 `<div class="aside-card">…</div>` 放置一句话记忆、
  常见误解或下一课预告；
- `{{CONTINUE}}`：提醒用户把答案和疑问粘贴回当前对话。

`{{CONTENT}}` 只放正文小节。每个小节使用唯一 `id`，标题统一写成
`<h2><span class="n">01</span>小标题</h2>`，让共享脚本自动生成目录和滚动高亮。
正文按 01–07 编号，至少包含：

1. **本课目标**：完成后能做什么；
2. **旧知识提取**：一个简短回忆问题，没有前置课时可以省略；
3. **核心解释**：只包含完成目标所需的知识；
4. **示例或演示**：把抽象概念落到具体场景；
5. **先预测再揭晓**：使用 `<details>` 或互动选择题；
6. **实际练习**：用户必须做出判断、解释或操作，并包含答案、检查步骤或提交格式；
7. **来源清单**：列出支撑本课关键事实的全部来源，并为每条来源设置稳定锚点。

课程导航已由模板固定为 08，只填写 `{{NAVIGATION}}`，不要在 `{{CONTENT}}` 中
重复创建导航小节。继续对话提示只填写 `{{CONTINUE}}`。

每节课都必须通过 `{{NAVIGATION}}` 直接链接：

- `lessons/` 中所有其他现有课程；
- 至少一个与本课相关的 `reference/*.html`；
- 存在时标明上一课和下一课。

创建新课程或参考资料后，更新所有旧课程的导航，使每节课都能到达当前全部课程和
相关参考资料。链接使用相对路径，交付前确认目标文件存在。第一课没有其他课程时，
仍需创建并链接一份紧凑的参考资料。

正文中的关键事实使用就近引用，例如：

```html
<p>
  授权码应是短期且一次性的凭据
  <a class="cite" href="#source-s1">S1</a>。
</p>
<section id="s-sources" class="sources">
  <h2><span class="n">07</span>来源</h2>
  <ol>
    <li id="source-s1">
      <a href="https://example.com/spec">规范名称</a>，相关章节。
    </li>
  </ol>
</section>
```

引用必须指向真实访问过的来源。课程末尾只有一份来源清单，正文通过锚点复用，
不在多个位置复制同一来源说明。

互动选择题使用模板支持的结构：

```html
<div class="quiz" data-quiz>
  <p class="quiz-label">选择题 1 / 1</p>
  <p class="quiz-question">问题</p>
  <button class="quiz-option" data-correct="false"
    data-explanation="为什么不对" type="button">
    <span class="opt-key">A</span><span>选项 A</span>
  </button>
  <button class="quiz-option" data-correct="true"
    data-explanation="为什么正确" type="button">
    <span class="opt-key">B</span><span>选项 B</span>
  </button>
  <p class="quiz-feedback" aria-live="polite"></p>
</div>
```

开放题可以使用：

```html
<div class="response">
  <label for="answer-1">写下你的解释</label>
  <p class="hint">写完后复制并粘贴回当前对话。</p>
  <textarea id="answer-1"></textarea>
  <button class="btn-ghost copy-response" data-target="answer-1" type="button">
    复制我的回答
  </button>
</div>
```

HTML 负责练习、揭晓和完成状态；AI 对话负责深度纠错和调整下一课。课程可以按需
使用远程字体、样式、图片、视频、交互库和网络 API；相关依赖在课程或共享 Assets 中
集中维护，避免每节课重复配置。

## 课程交付

课程文件通过验证后，尽量立即自动打开：

1. 优先使用当前宿主提供的打开文件或浏览器能力；
2. 没有专用能力时，根据操作系统运行 `open <file>`、`xdg-open <file>` 或
   `start "" <file>`；
3. 使用课程文件的绝对路径，避免工作目录变化导致打开错误；
4. 无图形界面、命令不可用或打开失败时，不把课程判定为失败；向用户返回绝对路径
   和手动打开方式。

自动打开只是交付动作，不构成用户已阅读或掌握的证据。

## 学习状态更新

生成课程后先等待用户互动。只有出现以下证据时才写学习记录：

- 用户正确解释或应用了非平凡概念；
- 用户完成练习并展示推理；
- 用户纠正了一个误解；
- 用户明确说明并证明已有前置知识；
- 学习目标因新理解发生变化。

仅点击“完成课程”或阅读过内容不构成掌握证据。

用户表达教学偏好时更新 `NOTES.md`。术语只有在用户能够正确使用后才进入
`GLOSSARY.md`。

## 参考资料

课程通常不会频繁重读，压缩后的参考资料会。适合反复查阅的内容写入
`reference/`，例如术语表、流程图、算法、命令速查和课程阶段总结。

## 本轮完成标准

- Mission 信息完整；若修改已有 Mission，变更已得到用户确认；
- 本课处于用户最近发展区；
- HTML 只解决一个紧凑目标；
- 复用了工作区共享 Assets，没有重复内联公共样式或脚本；
- 每节课链接全部其他现有课程和至少一个相关参考资料；
- 练习有可检查反馈；
- 每个关键事实都有就近引用，且来源清单可回溯；
- 课程文件通过验证脚本；
- 已尝试自动打开课程，或明确报告无法打开及绝对路径；
- 学习状态只根据证据更新。
