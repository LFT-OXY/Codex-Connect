# 本地用量仪表盘

**Status:** ready-for-agent

## Problem Statement

用户同时使用 Claude Code、Codex、Pi、oh-my-pi 等多个 Harness，其中绝大部分用量发生在终端里直接运行的 CLI，只有少量发生在 Codex Connect 中。Codex Connect 目前只能在 Composer 中显示「当前这个 Thread」的实时用量，关闭后即消失，没有任何历史累计，也不能按天、按 Harness、按项目查看。用户因此只能依赖另一个独立工具（TokenTracker）来了解自己一段时间内用了多少 Token、折合多少钱、主要花在哪个 Harness 和哪个项目上，希望在 Codex Connect 内直接看到这些。

## Solution

在设置对话框中新增「用量」标签页。页面读取本机四个 Harness 自己保存的原生会话记录，统计出 Local Usage，并按所选时间范围展示：

- 周期切换：日、周、月、总计、自定义。
- 所选范围的 Token 总数与 Estimated Cost，以及范围的起止日期。
- 按 Harness 的占比卡片（「全部」+ 各 Harness），显示占比与涉及的模型数；Pi、oh-my-pi 可展开到各 Provider。
- 统计块：最近 7 天、最近 30 天、日均、所选范围对话数；以及开始使用日期与活跃天数。
- 每日明细表：日期、总计、输入、输出、缓存、推理、对话数。
- 项目用量：按项目列出用量。

打开页面即自动增量读取新增记录，另有刷新按钮；第一次读取全部历史时显示进度。打开这两个大页面时设置对话框放大到接近整个窗口。

## User Stories

1. 作为多 Harness 用户，我想在 Codex Connect 的设置中打开「用量」页，以便不必切换到其他工具查看用量。
2. 作为多 Harness 用户，我想让终端里直接使用 CLI 产生的用量也被统计，以便看到真实的全部用量。
3. 作为多 Harness 用户，我想让在 Codex Connect 中运行的会话不被重复统计，以便数字准确。
4. 作为用户，我想按「日」查看今天的用量，以便掌握当天消耗。
5. 作为用户，我想按「周」查看本周（周一开始）的用量，以便按周复盘。
6. 作为用户，我想按「月」查看本月用量，以便按月复盘。
7. 作为用户，我想按「总计」查看长期用量，以便了解整体消耗。
8. 作为用户，我想用「自定义」选择任意起止日期，以便查看特定时段。
9. 作为用户，我想在页面中央看到所选范围的 Token 总数（大号数字），以便抓住重点。
10. 作为用户，我想在总数下方看到折算的费用，以便了解这些用量值多少钱。
11. 作为用户，我想看到所选范围的起止日期，以便确认统计区间。
12. 作为用户，我想看到一条按 Harness 占比着色的比例条，以便直观比较各 Harness 份额。
13. 作为用户，我想看到「全部」卡片显示 100% 与总模型数，以便了解整体。
14. 作为用户，我想看到每个 Harness 一张卡片，显示占比与模型数，以便比较各 Harness。
15. 作为 Pi / oh-my-pi 用户，我想在其卡片中展开查看各 Provider 的占比，以便知道同一 Harness 内用了哪些服务商。
16. 作为用户，我想让占比极小的 Harness 显示为「<0.01%」而不是 0%，以便知道它确实被用过。
17. 作为用户，我想看到最近 7 天与最近 30 天的用量，以便了解近期强度。
18. 作为用户，我想看到日均用量，以便了解日常水平。
19. 作为用户，我想看到所选范围的对话数，以便了解交互规模。
20. 作为用户，我想看到开始使用日期与活跃天数，以便了解使用历史。
21. 作为用户，我想看到每日明细表（日期、总计、输入、输出、缓存、推理、对话数），以便逐日核对。
22. 作为用户，我想让每日明细默认按日期倒序并可切换排序，以便先看到最近的数据。
23. 作为用户，我想在「项目用量」标签中看到每个项目的用量，以便知道 Token 花在哪些项目上。
24. 作为用户，我想让有 Git 远程地址的项目以 `owner/repo` 显示，没有的以文件夹名显示，以便识别所有项目，包括临时文件夹。
25. 作为用户，我想让大数字以 K/M/B 缩写显示，以便易读。
26. 作为用户，我想让统计按本机时区分日，以便「今天」与我的作息一致。
27. 作为用户，我想打开页面时自动读取新增记录，以便看到最新数据而不用手动操作。
28. 作为用户，我想点击刷新按钮立即重新读取新增记录，以便在长时间打开页面时更新数据。
29. 作为首次使用的用户，我想在读取全部历史时看到进度，以便知道还需等待多久。
30. 作为用户，我想在读取未完成时先看到已读部分的统计或明确的加载状态，以便页面不显得卡死。
31. 作为用户，我想让第二次及以后打开页面很快，以便不必每次等待全量读取。
32. 作为用户，我想让某个 Harness 的记录读取失败时其他 Harness 仍正常显示，并看到该 Harness 的失败提示，以便局部问题不影响整体。
33. 作为没安装某个 Harness 的用户，我想让该 Harness 不出现在卡片中，以便页面只展示我实际使用的工具。
34. 作为用户，我想让费用价格每天自动更新，以便新模型也有价格。
35. 作为离线用户，我想在无法联网时仍看到费用（使用内置价格），以便离线也能用。
36. 作为使用新模型的用户，当某模型没有价格时，我想让费用不计入该模型而不是报错，以便页面仍可用。
37. 作为用户，我想让设置对话框在「用量」页放大到接近整个窗口，以便仪表盘不拥挤。
38. 作为深色/浅色主题用户，我想让仪表盘在两种主题下都清晰，以便任何主题下都可读。
39. 作为中文或英文界面用户，我想让所有文案都有对应语言版本，以便界面语言一致。
40. 作为隐私敏感用户，我想让页面只展示聚合数字、不显示或传输任何对话内容，以便保护隐私。

## Implementation Decisions

- **Local Usage 的统一记录**：在公共 Adapter 契约中定义一种与 Harness 无关的用量记录：发生时间、可选 Provider、Model（只计对话的记录省略）、Native Session ID、可选工作目录、Token 分项（输入〔不含缓存〕、缓存读、缓存写、输出、推理）、对话数增量、可选的 Harness 自报费用、稳定去重键。记录不含任何消息正文，也不带 Harness 字段：Host 按读取来源归属，Adapter 不能冒充其他 Harness。Adapter 只交出终值（例如流式中的回复等待最终用量），可重复交出已读记录。
- **Adapter 可选能力**（ADR-0002）：新增一个只读的原生用量读取能力，形态与 `sessionImport` 一致为可选字段。输入为上一次返回的不透明游标（首次为空），输出为新增记录与新游标；游标由 Host 持久化，Adapter 自身无状态。实现者：Claude Code、Pi、oh-my-pi Adapter；官方 Codex 由 host-runtime 的 Codex 运行时提供同形状的读取器，结果中以 `harnessId: "codex"` 出现（Fork 重放不设边界硬跳过，而是沿用父会话记录的去重键由 Host 只计一次，见 issue 04）。各 Harness 的文件位置、字段映射、累计值差分、Fork 重放去重、子代理文件纳入等格式细节只存在于各自实现中。
- **Host 用量服务**（host-runtime 内新模块）：
  - 调用各来源的读取能力，按去重键去重（每个 Harness 内先到先得），把记录聚合为 UTC 半小时桶（Harness × Provider × Model × 工作目录；项目在查询时由工作目录派生，原生记录被清理后仍可按项目统计），与游标一起持久化在 codexhost 数据目录下的用量目录中（`usage/local-usage.json`）。
  - 单个来源失败只影响该来源，并在结果中带出失败状态。
  - 同一时刻只运行一次读取，并发请求共享同一次读取；不刷新的查询遇到进行中的读取时等待它完成。
  - 首次读取期间对外报告进度（已处理/总文件数）。
- **项目识别**：Host 由工作目录向上查找 Git 配置，取远程地址规范化为 `owner/repo`；没有远程时用文件夹名。结果按目录缓存。
- **计价**（Host 内，与 Harness 无关）：价格来源依次为 24 小时内的磁盘缓存 → 远程拉取 LiteLLM 价格表 → 过期缓存 → 随版本发布的内置快照；手工覆盖表始终优先。模型名匹配支持精确、别名、去后缀、去厂商前缀、最长子串兜底。费用 = 输入×输入价 + 输出×输出价 + 缓存读×缓存读价 + 缓存写×缓存写价 + 推理×输出价（推理已含在输出中的 Harness 不重复计）；有自报费用时优先使用。无价格的模型费用记 0，不报错。费用在查询时计算，价格更新后历史费用随之更新。手工覆盖与别名是随版本维护的源码表；推理不重复计由记录契约保证（`reasoning` 只在单独上报时非 0）；自报费用包括 0 时都优先使用，未知时 Adapter 省略该字段；价格只在 Host 首次加载时阻塞查询，过期后在后台刷新（见 issue 03）。
- **口径**（与 TokenTracker 一致）：Token 总数 = 输入 + 缓存读 + 缓存写 + 输出 + 推理（不重复计）；周从周一开始；「总计」= 最近 24 个月；7 天/30 天为对应滚动窗口总量；日均 = 最近 30 天总量 ÷ 其中有用量的天数；对话数 = 所选范围内对话数之和，各 Harness 口径不同（Claude Code：主会话中带文本的用户消息；Codex：每个非零 token_count 事件；Pi：每条 assistant 消息；oh-my-pi：同 Pi，每条 assistant 消息，已核实见 issue 06）；每日明细「缓存」列仅为缓存读；活跃天数 = 有用量的天数（Token > 0 且不晚于今天，覆盖全部已统计历史，不限「总计」范围；开始使用日期为其中最早一天；日均分母同样只计有 Token 的天）。
- **时区**：Renderer 在请求中带上本机时区，Host 按该时区把半小时桶归日。
- **RPC 契约**（shared-contracts）：新增用量查询方法：参数为周期（日/周/月/总计/自定义起止）、时区、是否强制刷新；结果为页面所需的完整视图数据（总数、费用、起止、Harness 卡片及 Provider 子项、统计块、每日明细、项目用量、各来源读取状态与进度）。Renderer 不接触原始记录。Host 路由在 app-server-host 注册；Renderer 客户端遵循现有 host-rpc 规范；该页始终使用本地 Host。
- **读取时机**：页面打开时发起查询（`refresh: true`），Host 先做增量读取再返回；切换周期不重新读取（`refresh: false`）；读取尚未完成时返回进度，Renderer 定时重查直至完成；刷新按钮强制重新增量读取。关闭设置后停止轮询。
- **Renderer 页面**：新增「用量」设置页，注册到设置页注册表（含图标、中英文标签）；使用 Tailwind 在设置 Shadow DOM 内实现；原生 DOM，不引入图表库。设置外壳支持按页面声明放大尺寸，「用量」页（以及后续的「会话」页）使用放大尺寸。
- **不改动**：Composer 用量药丸、Thread Usage 的实时链路与 mapping-store。

## Testing Decisions

- 好的测试只检验外部行为：给定一组原生记录文件，用量查询返回的数字与分组是否正确；不检验游标内部结构或私有函数。
- **主切入点：Host 用量查询请求**。在临时目录中放置四个 Harness 的伪造原生记录，用真实 Adapter（及 Codex 读取器）指向该目录，通过 Host 请求处理层发出用量查询，断言总数、费用、Harness 卡片、Provider 子项、统计块、每日明细、项目分组、时区归日、周期边界、增量读取（追加记录后只增加新部分）、去重、单来源失败隔离、首次读取进度。先例：`packages/host-runtime/test/harness-session-import.test.ts`（真实 PiAdapter + 临时目录 + 请求层）。
- **Adapter 切入点：各 Harness 原生记录解析**。覆盖各自格式边角：Claude Code 重复消息去重与子代理文件；Codex 累计值差分（含累计值重启）、缓存扣除、Fork 重放同键去重；Pi / oh-my-pi 的 Provider 与 cacheWrite、半行未写完的文件尾。先例：`packages/adapters/pi/test/pi-session-import.test.ts`、`packages/adapters/claude-code/test/claude-session-import.test.ts`。
- **计价**：纯函数测试，覆盖价格来源回退顺序、手工覆盖优先、模型名匹配规则、推理不重复计、无价格记 0。
- **契约**：shared-contracts 的 schema 测试（先例 `packages/shared-contracts/test/harness-session-import.test.ts`）。
- **渲染**：用假 DOM 检验页面根据视图数据画出正确结构（先例 `packages/renderer-extension/test/settings/accounts-usage.test.ts`）。
- **人工验证**：启动 Codex Connect 截图对照参考图；用本机全部真实记录，将同一时间段的 Token 总数、各 Harness 占比与费用和 TokenTracker 对比，差异需能解释。

## Out of Scope

- 2D/3D 热力图、趋势柱状图与预测值、Top 模型排行、分享卡片、拖拽布局。
- Claude Code、Codex、Pi、oh-my-pi 以外的 Harness（Grok、OpenCode、Qoder、Kimi 等）。
- 远程/SSH Host 上的用量。
- 在 Codex Desktop 主界面中增加整页路由或标题栏按钮。
- 后台定时读取（仅在页面打开与刷新时读取）。
- 云端同步、多设备汇总、导出。
- 按会话的用量列表与恢复（属于「会话用量与恢复」任务）。
