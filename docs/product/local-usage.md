# 用量统计

「设置 → 用量」统计本机各 Harness 原生会话记录中的 Local Usage，包括直接在终端运行 CLI 产生的用量。数据来源与解析归属见 [ADR-0001](../adr/0001-local-usage-from-native-session-records.md)、[ADR-0002](../adr/0002-native-usage-parsing-lives-in-adapters.md)。当前接入 Claude Code、官方 Codex、Pi 与 oh-my-pi；项目用量与首次读取进度尚未实现。

## 页面

- 打开「用量」页时设置对话框放大到接近整个窗口（四周各留 16px），内容区最宽 1400px；切到其他设置页后恢复原尺寸。窄窗口（≤720px）与其他页面一样占满窗口。
- 周期：日、周、月、总计、自定义，默认「周」。周从周一开始；「总计」为 23 个月前的当月 1 日到今天（最近 24 个月）；自定义选择起止日期后点「应用」生效，开始日期不能晚于结束日期、跨度不超过 3660 天。所有日期按本机时区划分。
- 中央大号数字是所选范围的 Token 总数，悬停可读完整数值；其下是该范围的 Estimated Cost（美元，保留两位小数，如 `$1,234.57`；大于 0 但不足半美分时显示 `<$0.01`），不另加「按 API 价格估算」之类的说明；再下是范围起止日期。
- 按 Harness 的占比横条与卡片：「全部」卡片显示 100% 与该范围内涉及的模型数；每个有用量的 Harness 一张卡片，显示占比（两位小数；大于 0 但不足 0.005% 时显示「<0.01%」）与模型数，按用量从高到低排列。范围内没有用量的 Harness 不出现。
- 记录了 Provider 的 Harness（Pi、oh-my-pi、官方 Codex）卡片底部有可展开的「Provider（数量）」，列出该范围内各 Provider 占该 Harness 用量的比例与模型数，按用量从高到低排列，默认收起；不记录 Provider 的 Harness（Claude Code）没有展开项。每次切换周期或刷新后重新收起。
- 统计块（在 Harness 卡片与每日明细之间）：最近 7 天、最近 30 天、日均、对话数四张卡片，数字以 K/M/B 缩写、悬停可读完整数值；下方一行是开始使用日期与活跃天数。
- 每日明细：日期、总计、输入、输出、缓存、推理、对话数，只列出有 Token 或对话的日期（跨零点时可能出现只有对话、总计为 0 的日期），按日期倒序。「缓存」列只含缓存读。
- 大数字以 K/M/B 缩写，最多两位小数（如 `12.35K`、`6.04B`）；四舍五入到下一级时进位（`999,999` 显示为 `1M`）。
- 范围内没有任何用量时显示总数 0 与「该周期内没有用量」，统计块照常显示在其下；本机从未统计到任何 Token 时不显示统计块。
- 页面只显示聚合数字，不显示也不传输任何消息正文、会话 ID 或工作目录。
- 本地 Host 不支持该查询时显示「本地 Host 不支持用量统计」，读取失败时显示可重试的失败提示。页面始终查询本地 Host，与当前 Composer 连接的 Host 无关。

## 口径

- Token 总数 = 输入（不含缓存）+ 缓存读 + 缓存写 + 输出 + 推理，不重复计。
- 最近 7 天 / 最近 30 天：截至今天（含今天）的 7 / 30 个日历日的 Token 总数，与所选周期无关。
- 日均 = 最近 30 天 Token 总数 ÷ 其中有 Token 的天数，四舍五入到整数；只有对话、没有 Token 的日期不计入分母；30 天内没有 Token 时为 0。
- 统计块的「对话数」是所选范围内的对话数之和，随周期切换变化。
- 活跃天数 = 有 Token 的日期数，开始使用日期 = 最早有 Token 的日期；二者统计全部已统计的历史，不受所选周期或「总计」24 个月范围限制。只有对话、没有 Token 的日期不算活跃；日期晚于今天的记录（例如本机时钟曾经偏快）不计入任何统计块。
- Estimated Cost = 输入 × 输入价 + 缓存读 × 缓存读价 + 缓存写 × 缓存写价 +（输出 + 推理）× 输出价。推理与输出互不包含：Harness 单独记录推理 Token 时（Pi、oh-my-pi 记录为输出的一部分，统计时从输出中拆出）推理列才有值，否则推理包含在输出中（如 Claude Code 的思考、Codex 的推理），推理列为 0，都不会重复计。Harness 在记录中自带费用时直接用该费用（包括 0，例如订阅通道），不再按价格计算。没有价格的模型费用记 0，不报错；只有对话、没有模型的记录不计费。估算费用按公开价格折算，订阅账号下可能远高于实际支出。
- 对话数按各 Harness 自身口径计，不可跨 Harness 比较。Claude Code 计主会话中用户输入的消息（字符串内容或含文本块），不计工具结果和子代理中的消息；Codex 计每次 Token 有增加的用量事件（约等于每次模型回复）；Pi 与 oh-my-pi 计每条 assistant 消息（每次模型回复，包括失败或中止、没有 Token 的回复）。
- Claude Code：读取 `$CLAUDE_CONFIG_DIR/projects`（默认 `~/.claude/projects`）下的主会话 `*.jsonl` 与 `<session>/subagents/*.jsonl`。同一次模型回复在记录中会重复写入多行（子代理记录还会先写入未完成的用量），按 `message.id + requestId` 只计一次，取最后一行的用量。最后一行没有 `stop_reason` 的回复可能仍在生成（工具结果可能先于最终用量写入），在该文件最近 1 小时内有写入时等下次读取再计；文件闲置超过 1 小时则按最后一行计入（被中断的回复）。Claude Code 不单独记录思考 Token，推理列为 0，思考量包含在输出中。
- Codex：读取 `$CODEX_HOME`（默认 `~/.codex`）下 `sessions/` 与 `archived_sessions/` 中的 `rollout-*.jsonl`，不经过 Codex app-server，也不依赖 Codex 插件，终端 CLI、Codex Desktop 与 Codex Connect 中的官方 Codex 会话都会计入。Codex 在每次模型回复后记录截至当时的累计用量，按相邻两次累计值之差计入；累计值没有变化的重复记录不计。累计值重新从较小值开始，或与本次回复用量相同（新 Fork 的会话、恢复后的会话）时，按本次回复用量计入。Codex 的输入包含缓存命中与缓存写入，统计时从输入中扣除，分别计入缓存读与缓存写。推理 Token 已包含在输出中，推理列为 0，费用按输出价只计一次。Model 取最近一次回合设置中的模型，Provider 取会话自身的 `model_provider`，工作目录取最近一次回合设置中的目录。Fork 出的会话开头会复制父会话的历史，这些复制的用量与父会话记录的去重键相同，只计一次；父会话记录在被读取之前就已删除时，复制的用量按 Fork 时间计入一次。会话归档（文件移到 `archived_sessions/`）后会被重新读取，已计的用量不会重复计入。
- Pi：读取 Pi 会话目录下（与 Pi CLI 相同：`PI_CODING_AGENT_SESSION_DIR`，否则 `$PI_CODING_AGENT_DIR/sessions`，默认 `~/.pi/agent/sessions`）所有子目录中的 `*.jsonl` 会话文件，包括子代理扩展保存在父会话目录内的子会话（如 `<会话>/tasks/`、`<运行>/run-N/`）；第一行不是 Pi 会话头的文件跳过。每条 assistant 消息的 `usage` 计一次：输入、缓存读、缓存写照原样计入；Pi 的推理 Token 是输出的一部分，统计时从输出中拆出放入推理列，Token 总数与费用不变。Provider 与 Model 取消息自身记录的值，工作目录取会话头的 `cwd`。Fork 与恢复会把原会话的消息原样复制到新文件，按消息的 entry id 与写入时间只计一次。Pi 只在消息完成后写入，因此不存在未完成的用量；文件末尾未写完的半行留到下次读取。Pi 自己记录的费用只在大于 0 时采用；为 0 时（订阅通道、自定义 Provider 未配置价格）无法区分免费与未知，按公开价格估算。
- oh-my-pi：读取 oh-my-pi 会话目录（与 omp 相同：`PI_CODING_AGENT_SESSION_DIR`，否则 `$PI_CODING_AGENT_DIR/sessions`，默认 `~/.omp/agent/sessions`，`PI_CONFIG_DIR` 可替换 `.omp`；使用默认目录且 `$XDG_DATA_HOME/omp` 存在时改读 `$XDG_DATA_HOME/omp/sessions`；不支持 omp 的配置档 `OMP_PROFILE`/`PI_PROFILE`）下所有子目录中的 `*.jsonl`，包括子代理会话（保存在以父会话文件命名的目录中，可多层嵌套）。会话文件开头可以是标题行，其后的第一条非标题行必须是会话头，否则跳过该文件。统计规则与 Pi 相同：每条 assistant 消息计一次用量与一次对话；推理 Token（`reasoningTokens`）是输出的一部分，统计时从输出中拆出；Provider 与 Model 取消息自身的值；按 entry id 与写入时间去重；oh-my-pi 自己记录的费用只在大于 0 时采用。

## 读取与缓存

- 打开页面时 Host 先增量读取新增记录再返回；切换周期只用已读取的数据，不重新读取；「刷新」按钮强制重新增量读取。关闭设置后不再读取，没有后台定时读取。
- 首次读取全部历史，之后按文件只读取新增的完整行；文件被替换或截断时从头重读，已计过的记录不会重复计入。同一时刻只有一次读取，并发请求共享它。
- Host 把游标、已计记录的短哈希和 UTC 半小时聚合桶（Harness × Provider × Model × 工作目录，工作目录供后续项目用量使用；自带费用的记录另成一桶并累计其费用）保存在 `${CODEXHOST_DATA_DIR:-~/.codexhost}/usage/local-usage.json`，查询时按请求的时区把桶归日。原生记录被 Harness 清理后，已统计的用量仍保留。文件损坏时从原生记录重建。
- 费用在每次查询时按当前价格计算，不写入统计数据；价格更新后，历史范围的费用随之变化。
- 价格来源依次为：24 小时内的本地价格缓存 → 远程拉取 LiteLLM 公开价格表（`model_prices_and_context_window.json`，10 秒超时，成功后写入缓存）→ 过期的本地缓存 → 随版本发布的内置价格快照。只采用文本模型（chat、responses、completion）的价格，LiteLLM 未列出的缓存价按 0 计。价格缓存在 `${CODEXHOST_DATA_DIR:-~/.codexhost}/usage/model-prices.json`。Host 进程内只有第一次加载价格时需要等待；此后价格过期（缓存或远程价格满 24 小时；离线回退到过期缓存或内置快照时为 1 小时后）时，查询先用已有价格返回，同时在后台重新获取，下一次查询起使用新价格，因此网络不通不会拖慢页面。
- 模型名匹配（不区分大小写）依次尝试：精确名称 → 别名 → 去掉 `[1m]`、`:high` 之类的变体后缀与 `-high`、`-thinking` 等推理强度后缀 → 去掉厂商前缀（如 `openai-codex/gpt-5.6-sol`；价格表中只有带厂商前缀的条目时，取名称排序最前的那个）→ 模型名中包含的最长已知模型名（只考虑至少 5 个字符且含字母和数字的名称，避免 `fast`、`o1` 之类的误配）。手工覆盖价格在每一步都先于 LiteLLM；手工覆盖与别名表随版本维护，当前为空（本机已见模型 LiteLLM 均能匹配）。
- 某个 Harness 读取失败或返回不合规记录（如多出正文字段）时整批不计，保留它上次的统计与游标，不影响其他 Harness；失败状态暂未在页面显示。
- 读取进行中切换周期时，查询等待本次读取完成后再返回，不会先显示旧数据。
- 用量读取是 Adapter 的可选能力 `nativeUsage.read(cursor)`，未安装或未实现该能力的 Harness 不参与统计。官方 Codex 没有 Adapter，由 Host 直接读取其 rollout，始终参与统计；本机没有 Codex 记录时不出现 Codex 卡片。
